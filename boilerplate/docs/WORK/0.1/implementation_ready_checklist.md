# Implementation Ready Checklist

- [ ] 対象ユーザーが定義されている
- [ ] 解く課題が定義されている
- [ ] 初期提供範囲と、その範囲に含めないものが定義されている
- [ ] 技術実現性検証、構想・利用体験検証、初期実用提供の位置付けが定義されている
- [ ] PoC が複数フェーズに跨る場合、各フェーズの検証範囲と完了条件が明記されている
- [ ] 主要な技術候補、制約、判断理由、事前検証事項が整理されている
- [ ] 採用技術に対応するTechnology Profileの追加要否が判断されている
- [ ] 選択済みprofileの初期採否、例外、未決事項が `docs/TECHNOLOGY/ADOPTION.md` に記録されている
- [ ] profile未収録技術について、公式一次情報の確認と制約整理が行われている
- [ ] クリティカルなセキュリティ要件が整理されている
- [ ] 成否を左右する性能要件と、負荷試験の要否が整理されている
- [ ] 課金要素、無償利用範囲、有償化の閾値、コスト判断基準が整理されている
- [ ] フェーズ分割が定義されている
- [ ] 現在フェーズの完了条件が定義されている
- [ ] UI / Interaction の要否と、現在フェーズで扱うかどうかが確認されている
- [ ] UIを扱う場合、対象と共有brand・対象別方針の範囲、必要な具体案・採否・媒体別検証が現在タスクへ接続されている（未決は検証タスクとして明示）
- [ ] プロダクト価値が UI / Interaction に依存する場合、その検証を PoC の範囲に含めている
- [ ] Web GUI がある場合、デザインモック / 仮実装を WBS に含めるか判断されている
- [ ] 外部公開 / 外部連携エンドポイントがある場合、FQDN 設計を WBS に含めるか判断されている
- [ ] WBS が実装可能な粒度まで分解されている
- [ ] 初期構想の各文書と関連 ADR の有効な決定を見直し、現在フェーズで行う事項を WBS と照合して抜けを補った
- [ ] 版の正本、セキュリティ確認の準備、プロジェクト固有のコーディング規約の適用要否と実施状況を確認した。着手前の必須項目は済ませ、先送りできる項目は理由と時期を現行 WBS または台帳に記録した
- [ ] 未解決の重要判断が列挙されている
- [ ] 受入条件またはテスト観点がある

見送り事項がない場合は、次の4項目を適用外として理由を記録する。

- [ ] 後続フェーズや長期バックログへ送る事項を、`deferred_items.md` または既存の台帳に記録した
- [ ] 現在フェーズの最後のマイルストーンで台帳の全項目を確認するタスクがある
- [ ] 現在フェーズの完了の定義に、台帳の全項目の確認と、反映先・送り先・不要理由の記録が含まれている
- [ ] `docs/ROADMAP.md` の関連アウトプットから台帳を参照している

## 実装着手の判断

- [ ] 上記の確認結果を踏まえ、利用者が実装を開始してよいと判断した

## セキュリティ確認

開始、重要変更、受入、公開・release前は `docs/SECURITY_ASSURANCE.md` と `security-gate` skillで必要な検査を確認する。Cloudflareは標準コード監査、OSVは依存検査。未導入時は具体計画と利用者承認後に導入・監査へ進む。Mantisの導入・実行は明示指示時だけとする。
