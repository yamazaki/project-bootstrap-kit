# Implementation Ready Checklist

- [ ] 対象ユーザーが定義されている
- [ ] 解く課題が定義されている
- [ ] 初期提供範囲と、その範囲に含めないものが定義されている
- [ ] 技術実現性検証、構想・利用体験検証、初期実用提供の位置付けが定義されている
- [ ] PoC が複数フェーズに跨る場合、各フェーズの検証範囲と完了条件が明記されている
- [ ] 主要な技術候補、制約、判断理由、事前検証事項が整理されている
- [ ] 採用技術に対応するTechnology Profileの追加要否が判断されている
- [ ] 選択済みprofileの初期採否、例外、未決事項が `docs/TECHNOLOGY/ADOPTION.md` に記録されている
- [ ] profile未収録技術について、公式一次情報の確認と制約整理が行われている
- [ ] クリティカルなセキュリティ要件が整理されている
- [ ] 成否を左右する性能要件と、負荷試験の要否が整理されている
- [ ] 課金要素、無償利用範囲、有償化の閾値、コスト判断基準が整理されている
- [ ] フェーズ分割が定義されている
- [ ] 現在フェーズの完了条件が定義されている
- [ ] UI / Interaction の要否と、現在フェーズで扱うかどうかが確認されている
- [ ] プロダクト価値が UI / Interaction に依存する場合、その検証を PoC の範囲に含めている
- [ ] Web GUI がある場合、デザインモック / 仮実装を WBS に含めるか判断されている
- [ ] 外部公開 / 外部連携エンドポイントがある場合、FQDN 設計を WBS に含めるか判断されている
- [ ] WBS が実装可能な粒度まで分解されている
- [ ] 未解決の重要判断が列挙されている
- [ ] 受入条件またはテスト観点がある
- [ ] 実装を開始してよいと判断できる
