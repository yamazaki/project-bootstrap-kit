# Operations Incidents

アラート、ログ、サービス停止、閾値超過、不審事象などの運用上の確認、影響判断、回復確認を管理する。障害であることや修正が必要であることを前提にしない。詳細な判別と線間遷移は `../../WORK_LINE_ROUTING.md` を正本とする。

## 受付と終了

1. 索引で類似事象と再利用できる調査手順を確認する
2. 次の `OPS-N` を採番し、受付時に索引行を追加する
3. 着手時にstatusを `🔄` へ更新する
4. 該当Runbook、安全不変条件、観測可能な事実を確認する
5. 事実、仮説、未確認事項を分離して調査する
6. `ops-{N}-{slug}.md` に事象、原因、影響、回復、判断、再利用可能な調査手順を記録する
7. 恒久修正が必要ならMNTを起票してリンクし、OPSは調査責務で閉じる

本番環境への変更、再起動、データ修復、外部通知などは、調査の一部として自動的に許可されたものとみなさない。影響と対象を示し、プロジェクトの承認境界に従う。

## 件別記録テンプレート

- ID / status / 検知日時 / 回復日時
- 事象と検知経路
- 既知の影響と影響範囲
- 事実 / 仮説 / 未確認事項
- 根本原因または現時点の判断
- 回復と確認結果
- 対応判断と承認を要した操作
- 再利用可能な調査手順
- 関連MNT、Runbook、監視改善
