# 作業線ルーティング

本ドキュメントは、計画開発と運用中の後続作業が並行するプロジェクトで、作業をどの管理線へ受け付けるかを定める正本である。

## 1. 判別方法

利用者が skill を明示した場合は、その作業線を第一候補とする。skill の指定がない場合は、AI が依頼内容と対象の状態から判別する。指定と実態が矛盾する場合は、変更や調査へ入る前に相違点を共有する。

| 作業線 | 対象 | 主な入口 | 記録先 |
|---|---|---|---|
| Epic | 現在フェーズの計画開発、新しい能力、重要な設計変更 | `ROADMAP.md`、`PLAN_PHASE_CURRENT.md`、最新session | WBS、`docs/WORK/<phase>.<milestone>/`、`agent_sessions/` |
| MNT | リリース済み・運用中の既存能力に対する修正、調整、互換性を保つ小規模追加 | `docs/WORK/maintenance/README.md` | `MNT-N` の索引行と件別記録 |
| OPS | アラート、ログ、停止、閾値超過、不審事象などの運用上の確認・調査・判断 | `docs/WORK/operations/README.md` と該当Runbook | `OPS-N` の索引行と件別記録 |
| ADV | 本プロジェクトの経験を、他プロジェクト、別の取り組み、プロジェクト化前の企画へ活用する相談・提案・レビュー | `docs/WORK/advisory/README.md` | `ADV-N` の索引行、件別記録、成果物正本 |

規模やセッション数は補助的な判断材料であり、主な基準は作業の起点と対象である。リリース済み部分の大きな修正が新しい能力やADR改訂を伴う場合は、MNTからEpicへの発展を検討する。

## 2. 明示起動と自動判定

- 利用者は `$maintenance-work`、`$operations-work`、`$experience-advisory`、または同等の明示指示で作業線を指定できる
- 明示指定がなくても、説明が各skillの適用条件に一致する場合はAIが該当skillを使用する
- AIは実質的な実装・調査・助言へ入る前に判別結果を短く示す
- 判別に必要な情報を安全な読み取りで確認できる場合は先に確認し、結果を変える重要な不明点だけを利用者へ確認する
- skillの明示起動または自動選択は作業線の指定であり、依頼範囲外のファイル変更、外部操作、commit、pushへの追加承認ではない

## 3. 作業線の遷移

- OPSで恒久修正が必要と判明した場合はMNTを起票し、OPSには原因、影響、回復、MNTへのリンクを残す
- MNTで新しい能力、重要な設計変更、複数マイルストーンの計画が必要と判明した場合はEpic化を利用者へ提案する
- ADVから本プロジェクトの変更が発生した場合はMNTまたはEpicを起票してリンクする
- 同じ事実を複数の線へ複製せず、各線の責務に沿った記録と相互リンクを使う

## 4. 記録の共通構造

各作業線は次の3層を使う。

1. `README.md` の索引表
   - 1案件1行の入口であり、statusと主要リンクは更新できる
2. 件別記録
   - 判断、検証、経過を日付付きで追記する
3. 成果物正本
   - 継続改訂する文書やRunbookは適切な `SPEC / ADR / REF`、またはADVの `assets/` に置く

索引を詳細本文で肥大化させない。完了済みの事実を訂正するときは、過去の判断を黙って消さず、訂正理由が追跡できる形にする。

statusは共通して `⬛ 未着手`、`🔄 進行中`、`✅ 完了`、`🚫 blocker` を使う。OPSとADVでは `👀 経過観察・相手待ち` も使用できる。

## 5. 正本への反映

作業線の記録は仕様や恒久ガイドラインの正本ではない。

- 振る舞いを変更した場合は `SPEC` を更新する
- 重要な設計判断を追加・変更した場合は `ADR` を更新する
- 継続利用するRunbook、運用手順、設計補足は `REF` へ昇格する
- 技術profileと異なる実証知識は `docs/TECHNOLOGY/ADOPTION.md` へ記録する
- リリース対象になった変更は `docs/VERSIONING.md` に従う
- 他プロジェクトにも有効な知識は `knowledge-feedback` skillの対象として検討する

## 6. bounded記録

secret、credential、個人情報、顧客データ、巨大な本文、不要な実URLや実IDを索引・件別記録・会話へ複製しない。必要な場合は、秘匿情報を除いた構造要約、件数、hash、placeholder、権限管理された正本への参照を使う。
