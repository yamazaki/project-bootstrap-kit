## 3. セッション運用方針

本フェーズでは、AI エージェントとの会話セッションを WBS 1件ずつ機械的に分けるのではなく、次の観点で束ねる。

### 3.1 基本原則

- 同じ前提、同じ用語、同じ schema を共有するタスクは同一セッションに束ねる
- 成果物の種類が大きく切り替わる地点でセッションを切る
  - 例: 要件整理 -> 設計
  - 例: 設計 -> 実装 / 検証
- 話題が広がりすぎて前提管理が難しくなる場合は、マイルストーン内でも分ける

### 3.2 本フェーズの推奨セッション粒度

- `x.1.01`
  - 単独セッション
  - 理由: 単独で前提を確定するタスクのため
- `x.1.02` + `x.1.03`
  - 同一セッション
  - 理由: 前提と成果物を強く共有するため

### 3.3 運用上の判断

- セッションを切るか迷った場合は、「前提の共有量」と「成果物の種類の変化」を優先判断基準とする

## 4. WBS（作業分解構造）

状態: `[ ]`=未着手, `[>]`=進行中, `[x]`=完了

作業開始時は、AI が実作業に入る前に対象タスクを `[>]` に変更する。
`[x]` は、AI の作業実施だけでなく、ユーザー確認、必要な E2E / 実機確認、最終レビューが完了した後に付与する。
レビュー待ち、受入確認待ち、E2E / 実機確認待ちのタスクは `[>]` のまま維持し、進捗ログに確認待ちとして記録する。

### x.1 マイルストーン名

- `[ ]` x.1.01: タスク名
- `[ ]` x.1.02: タスク名

### x.2 マイルストーン名

- `[ ]` x.2.01: タスク名
