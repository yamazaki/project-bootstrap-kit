# Commands and evidence contract

Run Node.js 22+ using the scripts directory adjacent to this skill. Paths below are examples; select real project and private output locations first. All commands are usable from the generated project without a kit checkout.

```text
node <skill>/scripts/security-gate.mjs plan --target <project> --ai-surface codex --trigger release --output-root <existing-private-directory> --network offline --database-root <reviewed-cache> --database-at <ISO-time> --save <external-plan.json>
node <skill>/scripts/security-gate.mjs install --plan <external-plan.json> --provider cloudflare --approve-plan <reviewed-digest>
node <skill>/scripts/security-gate.mjs install --plan <external-plan.json> --provider osv --approve-plan <reviewed-digest>
node <skill>/scripts/security-gate.mjs run-osv --plan <external-plan.json> --approve-plan <reviewed-digest> --database-root <reviewed-cache> --database-at <ISO-time> --save <external-osv-result.json>
node <skill>/scripts/security-gate.mjs import-cloudflare --plan <external-plan.json> --report <external-audit-directory> --approve-plan <reviewed-digest> --save <external-cloudflare-result.json>
node <skill>/scripts/security-gate.mjs gate --plan <external-plan.json> --osv-result <external-osv-result.json> --cloudflare-result <external-cloudflare-result.json>
```

Triggers: `start / change / dependencies / milestone / release / incident`. Repeat `--scope <relative-path>` for a bounded audit; default is the whole project. Scope cannot contain symlinks/special files. Snapshot excludes `.git`, `node_modules`, `.security-tools`, `.bootstrap-upgrade-diff`, `.DS_Store`, and the installed upstream `security-audit` directories. Code, settings, lockfiles, dirty/untracked content and the policy in scope are hashed. Unrelated docs may be excluded with an explained scope; release review must still cover the full release target and its baseline.

Dependency inputs are discovered from common lockfile names. Repeat `--input <relative-file>` to select supported SBOMs or additional files explicitly. Inputs must be in the snapshot. OSV emits JSON with all packages under an empty config override to avoid silently inheriting project ignores. Version 2.7.0: exit 0 clean, 1 vulnerabilities, 127 generic error, 128 no packages, 129 API failure, 130 invalid config. Only 0/1 and consistent valid nonempty inventory are accepted. An unsupported dependency/no input is not a clean scan: document applicability or an alternate reviewed check outside this automatic gate; it stays blocked here.

For Cloudflare, pass `--capabilities <external-json>` to `plan` after verifying actual capabilities. Its object uses `skillRecognized`, `independentAgents`, and `sandbox` booleans. These are recorded observations by the coordinator, never an implementation of isolation or proof of independence. A source-only run can use `sandbox=false`, provided metadata explicitly declares no target execution. Otherwise missing sandbox blocks import.

The `--save` path must also be inside the selected private output root, including after resolving its parent. The output directory must exist, be separate from the repository and its ancestors, and have private permissions (0700 on POSIX). Outputs are exclusively created, not overwritten. Plan flags authorize nothing by themselves: the calling agent must have actual human consent. A mutation plan expires after 24 hours; changed source/policy/adapter always requires regeneration. A changed plan must be checked against the previous human authorization before reuse.

Cloudflare import requires `run-metadata.json`, architecture, coverage ledger, findings and all three final reports; metadata must match source/scope/target and complete standard/deep mode. Both exact pinned upstream validators run before normalization. Planned/deferred/blocked coverage and dangling candidates remain gaps. `quick` is not accepted as the standard baseline. Metadata must also retain finite `budget`, observed `agent_invocations` and `duration_seconds` within the plan limits. `completed_at` is the actual ISO audit completion time; the importer preserves it as `completedAt` and rejects missing/invalid values or timestamps more than one minute in the future. Importing an old report never refreshes its age. Counts, timestamps and capability observations still require trusted coordinator review.

`import-osv` accepts an external `osv.json` plus `osv-context.json` containing `planDigest`, exact `inputs`, `network`, `databaseAt` and the observed `exitCode`. Prefer `run-osv`, which records these from the pinned binary. Importing owner-supplied records is a review boundary: do not assume a file proves execution. `gate` returns exit 2 for BLOCKED / REVIEW_REQUIRED, 0 for READY; operational/validation errors return 1. Tool messages are retained privately rather than printed with secrets. Read the error's conditions and the source reference instead of bypassing the gate.

Plans and results have `schemaVersion=1`, `kind`, a canonical SHA-256 `integrity`, source/policy/plan binding, role-specific evidence and state. The executable contract is `scripts/security-lib.mjs`; `providers.mjs` enforces raw provider-specific contracts. An integrity digest binds bytes, not authorship. Do not accept PR-provided READY files in CI without a trusted runner and artifact binding.

## Owner decisions and reuse

- `no-dependencies --plan <plan> --reason <reviewed-reason> --approve-plan <digest> --save <private-result>` records an owner-reviewed inventory only when no planned inputs or unresolved common package manifests exist. It is distinct from a zero-package OSV scan.
- `accept-findings --plan <plan> --provider <cloudflare|osv> --result <result> --finding <id> --reason <reason> --mitigation <control> --expires <ISO-time> --approve-plan <digest> --save <private-decisions>` accepts only identified non-high/critical findings with owner, mitigation and a bounded expiry. Pass the saved array to `gate --decisions <path>`. This is an explicit human decision, not an automatic suppression rule; it cannot waive execution/coverage failure or needs-validation boundaries.
- `reuse --plan <new-plan> --previous-plan <prior-plan> --result <prior-result> --approve-plan <new-digest> --save <private-result>` rebinds compatible same-source evidence without refreshing its completion/DB date. Code evidence can survive a DB-only update; dependency evidence cannot silently do so. Review actual prior execution and source equivalence before authorizing reuse.
- Local packages classified by OSV with `source=LOCAL` are a coverage gap until reviewed; OSV does not match those packages against advisories. Severity preserves named provider values (including MODERATE) and matching numeric group CVSS classifications. Missing severity stays unknown.
